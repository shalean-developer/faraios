This implements the distinct adapter required by the current-scope restore definition. It does not turn the previous synthetic approval into restore authority.

## Components and binding

scripts/t19-restore-host.mjs is a separate local-only CLI. --capture-sql prints read-only source admission SQL; --prepare REQUEST_JSON NEW_PRIVATE_DIRECTORY verifies admission and produces an unsigned fifteen-minute restore receipt; --run REQUEST_JSON NEW_PRIVATE_DIRECTORY APPROVAL_JSON accepts only t19-current-scope-isolated-restore-v1 under the independently pinned owner key. No hosted destination/connection option exists. The T11 restore CLI and config remain unchanged and are never called. Only its audited pure parameter-grant, sequence and verification helpers are imported; v2 scope is mandatory, so historical destination/catalog bindings are not selected.

The receipt binds request, source bundle (including transitive helper/config inputs), authenticated archive, private v2 profile, fresh source capture, retained compatibility index, complete transformed SQL plan, reviewed boundary SQL, original container/network/volume baseline, pinned runtime/Docker, host/boot/daemon/context and private journal. Execution verifies signature/scope/expiry, request/source and directory before reading the archive key, durably consumes the nonce, then rechecks every input and read-only host inspection before decryption and candidate mutation. Failed admission also consumes execution authority; no automatic retry. Preparation authenticates the archive privately but creates no containers. Capture and preparation are not restoration.

All private inputs must be root-owned regular single-link files under /root with no symlink or group/world access. Windows /mnt/c archive/key paths are deliberately refused. Existing Windows ACLs, immutable archive pin and a safe owner-only transfer method must be reviewed before preparing these Linux inputs; this source delivery does not copy or decrypt any owner archive. Keys are read only into host memory and their Buffer is zeroed after GCM authentication; JavaScript SQL strings cannot be guaranteed erased in memory. No key/archive host mount, provider secret or recovered SQL/row is written to a container filesystem, argv or journal.

## Candidate and replay

Reuses the accepted pinned bootstrap Host without changing its source bundle: the same images/ancestry/files, thirteen exited originals, fresh nonce-bound internal bridges, nonroot read-only containers, no published ports/binds/shared volumes, synthetic startup material and resource/cleanup gates. Auth/Storage API controls are separate from custody. Both services are removed before archive SQL enters PostgreSQL; no recovered Auth session or object request is served. Bootstrap phase input never contains the archive/key. The source-compiled custody overlay is applied only after independent restored-state verification.

The new pure planner checks member hashes, source/profile/capture, COPY/table/member/row coverage and sequence assignments. COPY rows remain opaque; psql metacommands and arbitrary top-level data SQL are rejected. Only reviewed native dump setup is replaced with fixed local limits. Schema transforms retain function bodies but reject transaction/role/connection escapes, privileged top-level objects, unreviewed extensions/languages/namespaces and role changes beyond the dump's reviewed settings. This is not a general-purpose SQL sandbox or approval of arbitrary dumps: it accepts only the authenticated, separately reviewed, exact plan whose bytes are owner-signed, inside a capability-free fresh candidate. Unsupported real input stops preparation for private review; no weakening/fallback exists.

Schema/role DDL runs as managed postgres within one explicit transaction. The fresh candidate's bootstrap-admin recovery connection supplies replica-mode COPY after full pre-data application/managed catalog equality; that connection is never provided to a web/worker service. Schema role, source parameter-grant preservation, original creation defaults and the already-audited working-days constraint reconstruction are exact plan inputs. Managed-schema-reference.sql is never replayed, provider ledgers are never overwritten and no repair loop exists. The SQL plan's admin/data versus managed/schema actor transition is explicit here and must be included in owner execution review; it was not authority inherited from the old bootstrap receipt.

The admin recovery connection suppresses statement/error-statement/duration/sample/auto-explain/parameter/object-audit logging before SQL input, then drops to the required actor for normal verification/probes. Client verbosity is SQLSTATE-only; execution errors record only outcome/code, not stderr, SQL or recovered fields. Candidate-owned logging state is session-only, not hosted configuration. Resource limits and the executable's bounded output/time controls remain mandatory. Any unknown command outcome fences mutations and returns quarantine; private diagnostics must be handled as potentially sensitive even when redacted.

Every covered table count/digest, portable catalog and extension set is checked before commit; enabled connections, external assets, foreign servers, large objects and runnable cron/net queues are refused. A new connection verifies committed data before sequence completion, and a further connection checks exact sequence values/is_called. setval is treated as nontransactional; failure removes only the disposable candidate and never claims rollback restored a sequence. Recovered data must fit the same bounded candidate resources; inputs over32MiB logical SQL are refused rather than increasing resources without review.

The fixed rollback-only business probe creates temporary synthetic identities/memberships against both recovered business controls, tests nonmember/foreign-business/staff reads and client-write denial, and checks an audited version update. It rolls back; all original row/sequence/catalog checks run again. This is database recovery evidence only, not recovered-accounting API/provider UAT. Custody gets its separate17-component/role/index/empty-state comparison and direct denied-role checks. Final managed equality and owned cleanup must pass before CURRENT_SCOPE_RESTORE_PASS.

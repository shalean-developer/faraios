# Preservation manifest and later adoption gates

SC-02 freezes 148 runtime/configuration/asset files by SHA-256 in `preservation-manifest.json`, all SQL statements and access sites in `contract-inventory.json`, and synthetic fixture bytes plus canonical section fingerprints in `tests/fixtures/sc02/fingerprints.json`. No real customer/financial/document values were exported. Fixture fingerprints are test evidence, **not hosted record fingerprints**.

| Scope | Exact values to preserve before/after later adoption | Reconciliation / stop rule |
|---|---|---|
| Every existing table | Complete existing rows and relationship keys, not only selected examples | Capture source catalogue and counts in a read-only repeatable snapshot; compare full original rows ordered by stable identity; zero deleted/orphan/changed originals outside reviewed allowlist. Current source has 17 public + 14 private tables; hosted Auth/Storage/provider objects are additional. |
| Business/account | businesses ID, owner_id, owner unique constraint, name/type/country/zone; Auth identity separate | Exact owner→business coverage; one owner membership seeded idempotently later. Never derive membership from staff/customer email. No new business created by invite acceptance. |
| Enquiry/request/customer | Original contact/submission, request UUID/shared ID, service/scope/currency/zone/address/preference, links/status/version, private notes/activity | Preserve nullable legacy scope and missing expiry. Explicit linking may only touch reviewed link/version fields when separately authorized. Existing pending request reserves nothing. |
| Quote | Original document/sender/token/expiry/decision/free confirmation/status/version/timestamps | No recalc/revalidation through new generic schema. Each old quote gets its own chain anchor; no inferred supersession or new customer decision. |
| Booking | Document, accepted quote, customer, address/instant/zone/duration/status/version and current assignments | Exactly one legacy visit per booking on initial adoption; deterministic mapping, rerun produces zero duplicates. Actual start/end unknown. Retain overlap and inactive-assignment evidence. No invented past assignment events. |
| Invoice / ledger | Issued numbers/tokens/sender/documents, due/issue/void/reason/predecessor, payment/reversal records, events, counters | Net ledger and counter equality; one active booking invoice; linked predecessor stays immutable. No ledger replay, currency conversion, tax backfill or inferred refund. |
| Draft/public/media | Separate draft/published catalogue and profile; public services/document/zone/slug/area flags; image bytes/IDs | Public JSON/content equality, URLs/canonical/sitemap/robots equality. Capability/account/settings changes never publish. All existing published businesses including Shalean retained. No republication in this package. |
| Waitlist / mail / operations | Consent/status/token hashes, delivery state/outboxes/leases/deduplication; private ingress/mail settings and operations state | Do not replay signup/send/cleanup, reset leases or regenerate customer tokens as migration. No customer sends/charges. Keep effective switches unchanged. |
| Backup/recovery | Dynamic catalogue, all new records/dependencies, sequences, functions, triggers, policies, table/column/schema/function ACLs, role defaults | Expand future backup manifest before activation. Verify isolated restore exact fingerprints and usable owner access; source file equality alone does not prove recovery. Storage bytes/external secrets handled separately. |

Later implementation requires a fresh read-only hosted/source drift inventory, approved affected-record manifest, dry-run mappings and bounded resumable batches. Build a deterministic source→target map and compare cardinality before writing. Stop on ambiguity, mismatch, unsupported historical shape or missing dependency; retain records for review. Additive new rows/columns must be specifically allowlisted; blanket removal of original-field comparisons is prohibited. Rerun adoption twice and rehearse interruption/recovery using synthetic data before preview activation.

Rollback must retain new memberships, visits, events and later user changes. Disable new creation or gate incompatible writers; do not restore old rows over current work, delete adopted work or silently deploy a single-visit writer after multi-visit data exists. Public/current readers and issued document links must remain usable.

Source manifest validation covers **bytes in this branch**, not a live comparison. No hosted backup/export, subscription check, schema/permission mutation, restore, publication, message or deployment is authorized or performed here.

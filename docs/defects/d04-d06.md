## Behavior

Long quote, booking and invoice IDs are internal hidden values; the manual UUID entry forms are removed. Existing paginated cards provide navigation beyond the first page. Opening an existing invoice preserves its issued bytes and financial history. There is no new bulk finance surface for receptionists.
- The two new selection forms submit the selected record's version. The delegated command verifies that version, scope and required state under row locks in the existing advisory-lock order. Selection metadata is restricted to these operations and stripped before typed dispatch. Old API callers remain compatible; existing scope/agreement/state checks still govern them. Missing/tampered UI selection versions fail; a stale selection must be reloaded and reviewed.
- **D05:** managers can edit saved staff names, contact details and active status through the existing versioned staff command. Receptionists/workers remain denied. Existing pending-invitation cancellation triggers remain unchanged; editing contact details does not transfer or revoke login identity. Owner access management stays separate. Assignments and audit/history remain intact; inactive worker resources lose operational assignment access through the existing active-resource check.
- **D06:** payment references are required with a 2–120-character rule in HTML and PHP; control characters and invalid UTF-8 fail clearly. Input remains available through D03 recovery. Stable per-form payment IDs reuse the existing database idempotency contract, so the same form submitted twice records one payment. Existing duplicate-reference, overpayment, currency, immutable-document and owner-only reversal rules remain unchanged.

## Contract and limits

Binding is `business_id + environment + provider + connection_id + generation + organization_id + credential_version`. The caller must use trusted stored bindings. Hosted adapters must independently enforce tenant/worker authority; knowledge of a binding is not authority. The service here uses existing owner sessions and has no HTTP route. Access-token return values are server-internal and must never become browser responses.

Custody reads require both the complete binding and its protected reference. `seal` prepares a new encrypted version; only coordinator `complete` publishes it. A hosted implementation must handle orphan staged versions and retention without losing cleanup/recovery material. No hosted custody, permissions, key rotation, backup or recovery mechanism has been selected.

Coordination methods are `current`, `claim`, `dispatch`, `complete`, `fail`. Claims have a unique lease and deadline. Dispatch records intent before synchronously invoking its effect callback at the fenced boundary, with no intervening async prerequisite. Completion atomically compares current generation, version, status, lease ID and expiry before advancing credential version. These are obligations for a future adapter, not proof that an arbitrary injected adapter satisfies them. Hosted dispatch/transaction ordering and crash windows need separate design and tests.

An expired pre-dispatch claim can be reclaimed with a new lease; the previous holder cannot dispatch. A dispatched claim cannot be reclaimed automatically, even after expiry or restart. Unknown rotated-refresh outcomes require recovery. Invalid grant makes reauthorisation required; late invalid grant after lease expiry becomes uncertain. Old-generation failures cannot disable a successor. Disconnect/reauthorisation advances generation in the dummy fixture and stale results cannot commit or populate usable cache entries.

Cache keys include the full binding/version. Every cache use revalidates existing server membership and current connection. Caller membership denial does not evict the shared token; authoritative connection rejection evicts that entry, and `clear()` purges process cache. Refresh lifetime is counted from dispatch start with an injected 1-second test safety margin, not response arrival. Hosted clock/skew/timeouts and active cache purge notification remain design work. Already-dispatched provider work cannot be recalled by disconnect; no token result grants an invoice worker permission to bypass Stage B dispatch checks.

The dummy coordinator is a synchronous Map, not distributed storage. Concurrent requests on one service share a promise. Another service sharing the fake coordinator receives `refresh_busy`; no unbounded retry/wait is implemented. Snapshot/reopen simulates a restart while retaining the custody key in the test process; it is not OS crash durability, disk recovery, KMS or rollback protection. Secrets still exist in process memory. Lost-key tests fail closed; no recovery guarantee is inferred.

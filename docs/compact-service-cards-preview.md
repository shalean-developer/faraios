## Optional service images

Owners can upload one PNG/JPEG/WebP per service, replace it, add accessible descriptive text, or remove it in the saved draft. Shared image preparation accepts source files up to10MB, bounds dimensions to2000px and output to150KB, and waits for preparation before the explicit save. Server request allowance250KB retains CSRF/origin verification and server content/dimension validation. SVG/unsupported formats and oversized raw files are rejected.

Immutable media is stored separately from lightweight catalogue photo references. A transactional authenticated invoker RPC commits the media and versioned draft together, rolling back both on stale versions. Owner-only RLS allows SELECT/INSERT and no UPDATE/DELETE on media. Published image retrieval uses a private bounded lookup through a public invoker wrapper, joining current visible/nonarchived service references to the same business and environment. Draft images require the current owner session. All image responses have no-store/nosniff and noindex. No data URLs, external image URLs or public storage bucket are introduced. Removed/replaced media remains retained for prior publication/history; no automatic deletion is introduced.

Images render only when configured, with accessible alt text, reserved8:5 proportions, cover cropping without stretching, and lazy loading. Cards without photos have no placeholder. Full descriptions and the five-step booking flow remain intact; booking snapshots carry only a small image reference, never image bytes.
